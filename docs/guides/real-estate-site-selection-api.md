# Real-estate and retail site-selection API

Gridics can supply parcel and zoning constraints for an explainable site-selection workflow. Start with supported property facts rather than an opaque score.

A typical flow is:

1. discover available search fields;
2. define the entitled Place or polygon;
3. filter on supported parcel/zoning criteria;
4. request only the fields needed for the decision;
5. apply customer-owned preference scoring separately.

See [advanced search](../../recipes/08-advanced-search/), [polygon search](../../recipes/09-polygon-search/), and [retail shortlist](../../recipes/12-retail-shortlist/).

The cookbook intentionally does not imply demographics, traffic, competitors, rent, drive times, or availability unless a public Gridics contract actually exposes them.
